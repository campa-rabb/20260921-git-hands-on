# ひだまり商店街

海の近くにある、少しレトロな架空の商店街の地域ポータルです。

暖かな色と店舗のイラストを見ながら、お店を探し、詳しい情報やおすすめの商品を読むことができます。Git・GitHub の共同開発ハンズオン向けの教材です。掲載する店舗・人物・地名・所在地・商品情報はすべて架空です。

## できること・完成イメージ

- 商店街の紹介、6 店舗のカード、商店街のお知らせを表示します。
- 店名・紹介文の検索とカテゴリの絞り込みを組み合わせられます。該当なしの案内も表示します。
- 店舗カードから、営業時間・定休日・所在地・おすすめ商品と価格を載せた詳細ページへ移動します。
- PC とスマートフォンの幅に対応しています。
- **店名や紹介文は HTML に直接書きます。** 一覧は `index.html`、詳細は `shops/` 内の各店舗の HTML です。
- 画像はリポジトリ内の SVG を使います。画像を用意しない場合は、ひな形の共通イラストをそのまま使えます。

HTML・CSS・JavaScript で構成しています。**参加者の PC に Node.js・npm は不要で、サーバーの起動やビルドも不要です。** 外部 API やデータベースは使いません。お気に入りや並び替えなどは、[演習用 Issue 案](docs/exercises.md)から追加できます。

## ローカルで開く

参加者が用意するのは Git、エディタ、ブラウザです。

1. 自分の fork を clone します。最初の PR までの手順は **[CONTRIBUTING.md](CONTRIBUTING.md)** を参照してください。
2. clone したフォルダの **`index.html` をダブルクリック**してブラウザで開きます。ブラウザの「ファイルを開く」から選んでも構いません。
3. 検索・カテゴリ絞り込み・店舗詳細を操作します。
4. HTML・CSS・JavaScript を編集して保存し、ブラウザを再読込すると変更が反映されます。

他の人の変更を取り込んだ後も、ブラウザを再読込するだけで確認できます。店舗ファイルの選択やデータの読み込み操作はありません。

## 自分のお店を追加する

店舗の追加では、**詳細ページを 1 枚作り、トップページにカードを 1 枚追加**します。一覧と詳細は別々の HTML なので、店名・カテゴリ・紹介文・画像が食い違わないよう確認してください。

### 1. 詳細ページをコピーする

他の人と重複しないファイル名を決めます。半角小文字の英数字とハイフンを使ってください。ここでは参加者番号を付けた `p01-nami-cafe` を使います。自分の番号や店名に置き換えます。

```sh
cp templates/shop-template.html shops/p01-nami-cafe.html
```

エディタでファイルをコピーし、名前を変更しても構いません。`templates/` のひな形を直接変更せず、コピー先を編集します。

### 2. 詳細ページを編集する

コピーした HTML をエディタで開き、コメントや見本を参考に、次の内容を書き換えます。

- ブラウザのタブに表示する `<title>` と、`<meta name="description">` の紹介文
- 店名（パンくずリストも含む）、カテゴリ、キャッチコピー、お店の紹介文
- 営業時間、定休日、商店街内の架空の所在地
- おすすめの商品・サービス、その説明と価格
- 画像の `src` と、画像の内容を伝える `alt`

価格は `600円` のように表示したい文字をそのまま書けます。店舗情報はすべて架空の内容にしてください。コピー元の店名が残っていないか、エディタの検索でも確認します。

### 3. 一覧にカードを追加する

1. `templates/shop-card.html` をエディタで開き、`<article class="shop-card" ...>` から対応する `</article>` までをコピーします。既存のカードをコピーしても構いません。
2. `index.html` の `id="shop-list"` の中にある、店舗カードの追加位置を示すコメントの手前に貼り付けます。他のカードを消さないようにします。
3. カードのリンク先を `shops/p01-nami-cafe.html` にします。
4. 店名、キャッチコピー、紹介文、所在地、カテゴリの表示と `data-category` を、自分のお店に合わせます。
5. 画像を使う場合は `src` と `alt` も書き換えます。

カテゴリの表示名と `data-category` は次の組み合わせを使います。新しいカテゴリ自体を作る作業は、店舗追加と分けるとレビューしやすくなります。

| `data-category` | カテゴリの表示名 |
| --- | --- |
| `food` | 飲食店 |
| `cafe` | 喫茶店 |
| `books` | 書店 |
| `goods` | 雑貨店 |
| `flowers` | 花屋 |

検索はカード内の店名（`h3`）、キャッチコピー（`.card-tagline`）、紹介文（`.card-description`）を対象にします。コピーしたカードのクラス名はそのまま使ってください。詳しい説明だけでなく、一覧の紹介文にもお店の特徴を書くと見つけやすくなります。

#### お店のイメージカラーを付ける（任意）

一覧カードの `<article>` と詳細ページの `<main>` に、同じ `data-shop` を指定します。値には店舗のファイル名から `.html` を除いた名前を使います。カテゴリが同じお店にも、それぞれ別の色を設定できます。

```html
<!-- index.html のカード -->
<article class="shop-card" data-category="cafe" data-shop="p01-nami-cafe">

<!-- shops/p01-nami-cafe.html の main -->
<main id="main" class="detail-main section-container" data-shop="p01-nami-cafe">
```

`src/styles.css` の店舗色の並びに、次のように3色を追加します。主色は文字が読みやすい濃い色、背景色と枠線色は同系色の淡い色にします。色を追加しなくても、商店街共通のテラコッタ色で表示されます。

```css
[data-shop="p01-nami-cafe"] {
  --shop-color: #3f6650; /* 文字・差し色 */
  --shop-tint: #eaf0e6; /* 淡い背景色 */
  --shop-line: #b8cab4; /* 枠線色 */
}
```

カードのライン・店名・カテゴリ・矢印と、詳細ページのキャッチコピー・価格・案内欄に同じ色が反映されます。色を変えたら、白・紙色・淡い背景のそれぞれで文字が読みやすいか確認してください。

### 4. 画像を付ける（任意）

**画像なしで追加する場合は、ひな形の共通イラストをそのまま使えば完成です。** `img` 要素を削除したり、`src` を空にしたりする必要はありません。

画像を付ける場合は、自作の SVG などを `images/shops/p01-nami-cafe.svg` に置きます。画像への相対パスは、HTML のある場所によって異なります。

```html
<!-- index.html のカード -->
<img src="images/shops/p01-nami-cafe.svg" alt="青いひさしのある喫茶店のイラスト">

<!-- shops/p01-nami-cafe.html の詳細 -->
<img src="../images/shops/p01-nami-cafe.svg" alt="青いひさしのある喫茶店のイラスト">
```

先頭の `/` や自分の PC の絶対パスは使いません。既存の `img` に付いているクラスやサイズの属性は残します。画像の権利を確認し、実在の個人情報を含めないでください。

### 5. 保存してブラウザで確認する

`index.html` を再読込し、自分のお店が表示されること、検索とカテゴリを組み合わせて探せることを確認します。カードを開き、詳細の文章・画像・一覧へ戻るリンクも確認します。詳細 HTML を直接開くこともできます。

約 40 人で作業するため、共通の `index.html` は複数人が編集します。自分のカードだけを追加し、ファイル全体の整形や他のカードの並び替えは避けると変更を確認しやすくなります。作業開始前や PR のレビュー中に `upstream/main` を取り込みます。同じ場所にカードを追加するとコンフリクトが起こる場合は、両方のカードを残すよう相談して解消してください。詳しくは [CONTRIBUTING.md](CONTRIBUTING.md) を参照してください。

## 確認と CI

**ローカルのビルド作業はありません。** HTML をそのまま公開できます。参加者はブラウザで、次を確認してください。

- 一覧と詳細の店名・カテゴリ・紹介内容が一致している
- 店名・紹介文の検索、カテゴリとの併用、該当なしの案内が動く
- 店舗カード・一覧への戻り・画像が正常に表示される
- PC とスマートフォン幅で文字やボタンが重ならない
- 変更していない店舗やお知らせも表示される

PR を送ると GitHub Actions の **Check site** が HTML のリンク・画像の参照先、重複する HTML ID などを確認します。画面の見た目や文章の意味は自動検証できないため、ブラウザでの確認も行ってください。CI は `pull_request` イベントで実行し、fork からの PR に秘密情報は不要です。

講師や検証スクリプトを編集する人が手元でも実行したい場合のみ、Python 3 がある環境で次を実行します。追加パッケージは不要です。**参加者に Python のインストールは必要ありません。**

```sh
python3 scripts/check-links.py
```

## GitHub Pages へ公開する（講師向け）

この教材の作成時点では、リポジトリの作成やサイトの公開は行っていません。公開するときは講師が次の設定を行います。

1. GitHub に **public** リポジトリを用意し、このコードを push します。既定ブランチを `main` にします。
2. 下記の置換表を使い、`CONTRIBUTING.md` のリポジトリ情報を実際の情報に置き換えます。
3. **Settings → Actions → General** で GitHub Actions と、このリポジトリで使う公式 Actions を利用できるようにします。fork からの初回 PR は、GitHub の設定により講師の workflow 実行承認が必要になることがあります。
4. **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
5. **Actions → Deploy GitHub Pages → Run workflow** を開き、ブランチ **main** を選んで手動実行します。検証後、HTML・CSS・JavaScript・画像をそのまま公開します。
6. workflow の結果か Settings → Pages に表示される URL を開き、一覧・詳細・画像を確認します。

公開 URL の例は `https://INSTRUCTOR_ACCOUNT.github.io/REPOSITORY_NAME/` です。リンク・画像・スクリプトには相対パスを使うため、リポジトリ名のサブディレクトリ配下でも表示できます。`https://INSTRUCTOR_ACCOUNT.github.io/REPOSITORY_NAME/shops/komorebi-kissa.html` のような店舗詳細の URL も直接開けます。

公開 workflow は **手動実行のみ**で、`main` 以外からは公開しません。PR 作成やマージだけでは公開されないので、更新を公開するときは手順 5 を再実行してください。workflow は公開対象の `index.html`、`404.html`、`shops/`、`src/`、`images/`、`favicon.svg` を一時フォルダ `_site/` に集めてアップロードします。参加者がこのフォルダを作る必要はなく、リポジトリにもコミットしません。公開 workflow のみ GitHub 標準の Pages 用権限を使い、追加の秘密情報は不要です。

### 講師が事前に決める項目

| 表記 | 置き換える内容 |
| --- | --- |
| `INSTRUCTOR_ACCOUNT` | 元リポジトリの所有者の GitHub アカウントまたは Organization |
| `REPOSITORY_NAME` | 元リポジトリ名 |
| `YOUR_ACCOUNT` | 各参加者自身の GitHub アカウント（参加者が置き換える） |
| `p01` | 各参加者の番号または重複しない短い識別子 |

40 人分のファイル名の接頭辞、Issue の担当、レビュー担当、マージ担当を決めてください。店舗追加を小グループごとに進め、取り込みの時間を挟むと、共通の `index.html` の変更を整理しやすくなります。必要に応じて `main` の保護ルールを設定し、PR と **Check site** の成功をマージ条件にします。fork の許可、参加者が Issue・PR を作成できることも確認してください。公開教材の再利用方針に応じて、講師が適切なライセンスを選んで追加してください。
